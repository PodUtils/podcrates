# fuzz

The fuzz targets of the parsers of podcrates (cargo-fuzz and libFuzzer;
`docs/design.md`, section 8, step 4; T-017). This directory is a cargo
workspace of its own: the root workspace excludes it, so the library
crates do not build libFuzzer's C++.

## Run

```sh
sh scripts/fuzz.sh 60                 # each target for 60 s
sh scripts/fuzz.sh 300 proxy_url      # one target for 300 s
cargo check --manifest-path fuzz/Cargo.toml --bins   # the build, on stable Rust
cargo test --manifest-path fuzz/Cargo.toml --lib     # the stable test
```

* `scripts/fuzz.sh` pins the nightly Rust and the version of cargo-fuzz.
  It needs Linux with glibc and a C++ compiler. A crash fails the run,
  and its input stays in `fuzz/artifacts/TARGET/`.
* `.github/workflows/fuzz.yml` runs each target each week and by hand,
  first with the plant `fuzz-one-line-escape`, which must crash.
  `ci.yml` runs the build and the stable test on each push.
* The dev profile of this workspace optimizes the crates under test
  (`opt-level = 2`): the stable test runs the crypto of `pod-wg` and
  `pod-e2e` on 2000 mutations of each seed, which takes minutes with no
  optimization.
* A crash input becomes a unit test of its crate first, then the repair.

## Layout

| Path | What |
| --- | --- |
| `src/targets.rs`, `src/targets/` | the body of each target: the parser that it runs and what it checks (`targets/actions.rs`: the expressions and the workflow files of `pod-actions-expr` and `pod-actions-workflow`; `targets/results.rs`: the requests of a client of the results API to the stores of `pod-actions-results`; `targets/cloudflare.rs`: the edge of Cloudflare and the configuration of a tunnel of `pod-cloudflare`; `targets/broker.rs`: the head of a request inside a tunnel and the swap and the scrub of the TLS end of `pod-broker`; `targets/devtunnel.rs`: the connect information of `pod-devtunnel`; `targets/egress.rs`: the packets of a Wisp server of `pod-egress`; `targets/job.rs`: the records of `pod-job`; `targets/link.rs`: the frames, the ARQ, the reader of HTTP/1.1 and of SSE of the poll carriers and the stream of KCP of `pod-link`; `targets/qga.rs`: the answers of the guest agent of `pod-qga`; `targets/turn.rs`: the codec of STUN of `pod-turn`; `targets/udf.rs`: the UDF reader of `pod-udf`; `targets/netlab.rs`: the counters of `pod-netlab`; `targets/podvm.rs`: the parsers of podvm; `targets/session.rs`: the records, the handover state and the UDP frames of `pod-session`; `targets/wormhole.rs`: the packets of an MQTT broker and the messages of a Nostr relay; `targets/tpm.rs`: the response of a TPM and the key file of `pod-tpm`) |
| `src/lib.rs` | `TARGETS`, and the checks that more than one target uses |
| `src/tests.rs` | each target on its seeds and on 2000 mutations of them, on stable Rust; each target has its binary and its seeds |
| `src/record_seeds.rs` | the seeds of `e2e_record`: the test that they are the sealed records that it makes, and its writer (an ignored test) |
| `src/arq_seeds.rs`, `src/kcp_seeds.rs`, `src/poll_seeds.rs` | the seeds of `link_arq`, `link_kcp` and `link_poll_wire`: the test that they are the ones on disk, and their writers (ignored tests) |
| `src/tpm_seeds.rs` | the seeds of `tpm_response` and `tpm_keyfile`: the test that they are the responses of the TPM in software of `pod-tpm` and its key files, and their writer (an ignored test) |
| `fuzz_targets/NAME.rs` | the binary of a target: it calls `targets::NAME` |
| `seeds/NAME/` | the seeds of a target, small files; libFuzzer reads them, and adds what it finds to `corpus/NAME/` (not in git) |
