# podcrates v0.21.0

The twenty-first release of podcrates. For podvm: `pod-incus`, a client
of the REST API of incus on its Unix socket (PodUtils/podvm#253). For
each consumer: one temporary name for each private store of `pod-core`
and one pin at a time in `pod-identity` (T-195). For podrunner: the
socket of `pod-broker` has its mode from the first instant (T-196, the
fix of PodUtils/podnet#444).

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-incus` | new: a client of the REST API of incus 6.0 and later on its Unix socket, with no `incus` binary; new code from the API of lxc/incus at `63377d9`. `Client` with `Settings` (the socket, the project, the user agent, the limits); `server` and `Server::check` (the extensions of `NEEDED`); `import_image` from a stream (unified, or split as multipart), `create_alias`; `create_instance`, `set_state`, `start`, `stop`, `instances`, `instance`, `delete_instance`, `console_log`; `exec_recorded` (`record-output`) and `exec_attached` (the websockets `control`, `0`, `1`, `2` on the session of `pod-ws`); `get_file`, `put_file`; `operation`, `wait`, `wait_success`, `cancel`. `Error` names the call with no query (no secret of a websocket) and its kind (T-179) | podvm (PodUtils/podvm@T-1718) |
| `pod-core` | `files`: the temporary file of a private store is `.NAME.PID.N.tmp`, with a counter of the process; two threads that store one name at once no longer tear the file (T-195) | each |
| `pod-identity` | `pins`: a lock of the process around the read, the add and the store of a pin; two pins at once keep both lines. Two processes are not held (call C54) (T-195) | podssh |
| `pod-broker` | `control::bind_unix` binds in a new directory of mode 0700 beside the path, sets the mode there, and moves the socket to the path by `link(2)`; another user cannot connect before the mode is set. A stage that does not fit in `sun_path` binds at the path (T-196) | podrunner |

## How a consumer takes it

Each podcrates dependency names the tag `v0.21.0`. podvm adds
`pod-incus` and replaces its own client with it; the README of the crate
maps each call of podvm's table to a call of the crate. The crate needs
incus 6.0 or later; `Server::check` names an extension that is missing.

## Breaking

- `pod_broker::control::bind_unix`: the listener keeps the name of its
  bind, the path in the stage, which is removed after the move. A caller
  that reads `local_addr` of the listener gets that path, not the path of
  the socket. A path that another bind takes while the bind runs gives
  `AddrInUse`.

## Known defect

- `pod-netstack`: Reno and CUBIC of smoltcp 0.14 grow the window by one
  segment for each ACK; on a link that gives one ACK for each round trip
  they are slow (T-188, open). The default (no controller) is not.
- `pod-gsr` on Windows ARM64: a test process ends with
  `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
