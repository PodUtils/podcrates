# podcrates v0.11.0

The eleventh release of podcrates: `pod-rootfs` (the completion of a root
file system) from podvm, with eleven fixes of podvm's code; `pod-enter`
classifies and stages a payload of any size with bounded memory; the
tests of podvm's fix of the whiteout escape in `pod-extract`.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-rootfs` | new: the completion of a root file system on Linux, with no privilege: `complete(rootfs, &Settings, &mut dyn reach::Probe)`, `Settings`, `Names`, `HostBundle`, `Report` with its `Fixup` and `Step` rows, `write::Root` (each write held in the root), `reach::Probe` (the caller's HTTPS check of a mirror) (T-058; call C40). Fixed against podvm's code: an image whose `dev` links out of the root changed host files; a fifo at a configuration or CA path stopped the completion; a node on a `nodev` file system read as a device; a grown host bundle asked for no rehash; the C library was not found on armv7, i686, riscv64, ppc64le, s390x and loongarch64; a file of the image behind a link was replaced; the probe of a mirror got the user part of a URL; a line end in an added host wrote lines into `/etc/hosts`; a mount point with a space did not match; the bytes of the image's CA bundle changed on append; a mode change by name could follow a link | podvm (`adoption/podvm/pod-rootfs.patch`) |
| `pod-enter` | `abi::Elf::read` reads the headers and the needed sections with `pread` (`READ_CEILING`, 64 MiB for one table or section); `abi::interp_of` reads a header past the head as unknown, never static; `abi::interp_of_file`; `ladder::payload_head` (`Payload { path, len, head }`, `file()`) replaces `payload_bytes` and `PAYLOAD_CEILING`; `memfd::stage_file` and `stage_file_with` copy in chunks of `STAGE_CHUNK` (1 MiB). | `pod-extract` | podvm's tests of the whiteout escape (`.wh...`, `../.wh.x`, `d/.wh..`, an absolute whiteout): no gap in the crate (T-141, PodUtils/podvm#221) | podvm (`adoption/podvm/pod-extract.patch`) |
| `pod-hostprobe` | `sys::{O_NONBLOCK, S_IFIFO}` (T-058) | `pod-rootfs` |
| the others | no change | |

## How a consumer takes it

Each podcrates dependency names the tag `v0.11.0`. podvm applies
`adoption/podvm/pod-extract.patch`, then `adoption/podvm/pod-rootfs.patch`
(both made on podvm `20ea781`; each applies clean in that order), and runs
the lines of each `.run`.

## Breaking

- `pod_enter::ladder::payload_bytes` and `PAYLOAD_CEILING` are gone: call
  `payload_head` and give `&p.head` to the checks of the payload. A
  payload staged into a memfd goes through `memfd::stage_file` with the
  open file (`crates/pod-enter/README.md`, "Adoption map").
- `pod_enter::abi::interp_of` returns an error for a program header or a
  `PT_INTERP` path past the bytes given, where it returned `Ok(None)`.

## Known defect

- `pod-gsr` on Windows ARM64: a test process ends with
  `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
