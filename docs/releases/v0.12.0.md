# podcrates v0.12.0

The twelfth release of podcrates: `pod-enter` takes the volume pairs of a
run, and resolves the workdir and the first program through them
(PodUtils/podvm#224); the `#!` and `$0` helpers of `pod-enter`;
`Statfs::f_flags` and a `statx` fallback in `pod-hostprobe`.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-enter` | `userland::Volume` and `userland::Maps` (`of_root`, `new`, `volume_at`): the root pair and the volume pairs of a run, each side checked with its own name. `userland_maps_table(&names, &maps)` and `userland_volume_table`. `abi::GuestRoot`, one guest-to-host resolver over the table (the longest guest prefix wins; a link in a volume is read as a guest path again, so it does not reach the host beside the volume). `check_workdir`, `ladder::{resolve_payload, payload_head, guest_exe, guest_invoked}`, `userland::{loader_plan, lib_dirs, invocation_path}` and `abi::{resolve_in, resolve_dir_in}` take a `GuestRoot`; a path is one. The userland child does not follow an image link in `-w` on the host (T-144). `memfd::shebang_parts`, `memfd::SHEBANG_HEAD`, `ladder::guest_invoked`; the text of the script route is corrected (T-137) | podvm |
| `pod-hostprobe` | `Statfs::f_flags`, `Statfs::flag`, the `ST_*` flags (T-145). `fstatat` falls back to `statx` where the kernel has no `newfstatat` (loongarch64 before Linux 6.11, T-148) | podvm, `pod-enter`, `pod-extract`, `pod-rootfs` |
| `pod-guest` | a test of a real emulator under KVM; `guest.yml` runs the tests of a real emulator each week (T-138) | podvm |
| the others | no change | |

## How a consumer takes it

Each podcrates dependency names the tag `v0.12.0`. podvm takes `v0.11.0`
first (`pod-extract.patch`, then `pod-rootfs.patch`; GitHub #46), then
moves to `v0.12.0` and changes its calls as `crates/pod-enter/README.md`,
"Adoption map", says. podssh and podnet need no code change.

## Breaking

- `pod_enter::spawn_userland` and `run_userland` take `&Maps` after the
  plan. A run with no volume gives `Maps::of_root(rootfs)`.
- `pod_enter::userland_maps_table` takes `&Maps`, not the rootfs.

## Known defect

- `pod-gsr` on Windows ARM64: a test process ends with
  `STATUS_ACCESS_VIOLATION` (T-131, open).
- Three tests of `pod-enter` fail under qemu-user only (T-149, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
