# podcrates v0.10.0

The tenth release of podcrates: `pod-oci` (the OCI registry client) and
`pod-extract` (the rootless apply of a layer), both from podvm, with a fix
of a whiteout escape; the public proxy lists and nodes of podssh.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-oci` | new: the OCI registry client: `Client` over the caller's blocking client of `pod-proxy` and trust (`manifest`, `tags`, `blob`), `reference`, `digest`, `spec`, `platform`, `credentials` (`Files`, `Logins`), `transport`, `trust`, `pull` (`resolve`, `fetch_parallel` into the caller's store), `layout` (T-056; call C38) | podvm (`adoption/podvm/pod-oci.patch`) |
| `pod-extract` | new: the rootless apply of an OCI layer: `extract(&Settings, image, &[Layer], &Place)`, `Place`, `remove_tree`, the modules `apply`, `layer`, `remove`, `safety`, `sidecar`, `whiteout` (T-057; call C39). Fixed against podvm's code: a whiteout named `.wh...` at the root of a layer, or `../.wh.x` with no `openat2`, deleted outside the destination; each whiteout path now gets the check of each other entry, and a whiteout of `.` or `..` refuses the layer. A mode that the kernel refuses is written to the sidecar as it stays on disk | podvm (`adoption/podvm/pod-extract.patch`) |
| `pod-core` | `Stage::Registry`: an answer, a document or a digest of a registry (T-056) | `pod-oci`, each consumer |
| `pod-hostprobe` | `sys::{EIO, E2BIG, ENOTDIR, EISDIR, ELOOP}` (T-057) | `pod-extract` |
| `pod-services` | the kinds `proxy-list` (3 lists) and `proxy-node` (6 nodes) for podssh's last fallback, with a watch kind `proxy-banner` (T-133, PodUtils/podssh#177); no `wisp-public` server qualifies (T-130, PodUtils/podssh#175) | podssh |
| the others | no change | |

## How a consumer takes it

Each podcrates dependency names the tag `v0.10.0`. podvm applies
`adoption/podvm/pod-oci.patch`, then `adoption/podvm/pod-extract.patch`
(made on podvm `2616bd7`), and runs the lines of each `.run`; with
`--3way`, the second conflicts in four files that `pod-extract.run` names.

## Breaking

- `pod_core::Stage` has the variant `Registry`. A `match` with no `_` arm
  adds it.

## Known defect

- `pod-gsr` on Windows ARM64: a test process ends with
  `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
