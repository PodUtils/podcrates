# podcrates v0.87.0

The eighty-seventh release of podcrates. It carries each change of `main`
after `v0.86.0`. It has no new crate. It carries a security fix of
`pod-enter` for podvm and podrunner (PodUtils/podvm#695, from
PodUtils/podrunner#378 and PodUtils/podvm#693): on the namespace rung, a
payload of uid 0 could remount a `:ro` volume writable and leave the tree
of the image. The rung now enters the tree with `pivot_root`, the payload
of uid 0 runs in a nested user and mount namespace (host root too, call
C990), a join enters the owner of the mounts first, and `Plan::read_only_root`
gives a read-only root (T-1560, T-1561). For podvm, it also carries the
asks PodUtils/podvm#675, #677, #678, #680, #683 and #692 (asks 1, 3 and 4).
For podrunner, it carries PodUtils/podrunner#367, #373, #375 and #379 to
#381. For podnet, it carries PodUtils/podnet#779 to #783 (#782 asks 1 to
4) and #785. For podssh, it carries PodUtils/podssh#358 and the removal of
`pod_relay::grant::openssh_public`. It also carries the ports of
`upstream.yml` 45838753274 (T-1517 to T-1521), the DERP set of Tailscale
(T-1513) and the fixes of the nightly 45806031483 (T-1600, T-1601).

## Breaking changes

A consumer reads this section first. Each item gives the fix.

- `pod_enter::Plan` has the new public field `read_only_root: bool`
  (T-1561). `Plan` is not `non_exhaustive` and has no `Default`: each struct
  literal adds `read_only_root: false` (or `true` in place of podvm's
  seal). A literal with `..plan` builds. podvm:
  `crates/podvm/src/run/foreground.rs`,
  `crates/podvm/src/run/foreground/pid_ns.rs`,
  `crates/podvm/src/exec/command.rs`, `crates/podvm/src/exec/enter.rs`,
  `crates/podvm/src/complete/strict.rs`,
  `crates/podvm-supervise/src/launcher.rs` and the tests
  `crates/podvm/src/ladder/tests.rs` and
  `crates/podvm-enter/src/confine/tests.rs` (the literal at its line 196;
  the one with `..plan` builds). podrunner builds no `Plan`.
- `pod-enter`, the namespace rung (T-1560, call C990): a payload of uid 0
  (uid 0 of the user namespace of the rung, uid 0 of a user namespace of
  the caller with no ids, and host root) runs in a nested user namespace
  with the identity of the outer maps, and in its own mount namespace. A
  payload of host root holds no capability of the initial user namespace:
  it cannot load a module, set the clock, open a raw socket or bind a port
  under 1024 of the host's network. No `Plan` setting keeps the old
  behaviour; a consumer that needs one asks by a COORD issue. A payload
  with no ids reads `0 0 1` in `/proc/self/uid_map` (it read `0 UID 1`).
  The rung enters the tree with `pivot_root`, not `chroot`: the old root is
  detached, so no path of the host is in the mount namespace of the
  payload.
- `pod_hostprobe::Settings` has the new public field `emulator:
  Option<PathBuf>` (T-1424). `Settings` has `Default` and is not
  `non_exhaustive`: a literal with no `..Settings::default()` adds
  `emulator: None`. podvm: `settings` of `crates/podvm-probe/src/lib.rs`.
  podrunner: `probe_settings` of `crates/podrunner/src/doctor.rs`.
- `pod_rootfs::Settings` has the new public field `keep_existing_hosts:
  bool` (T-1582). `Settings` has `Default`: a literal with no
  `..Default::default()` adds the field. podvm: `settings` of
  `crates/podvm-complete/src/lib.rs` (`false`, and `true` for the
  completion of an `exec`).
- `pod_supervise::start` and `launcher::start` have a third type
  parameter `E: Into<EntryFailure>` (T-1581). A call that infers the
  parameters builds with no change. A call that names them does not build:
  podvm `crates/podvm-supervise/tests/restart_clears_end.rs` (twice)
  writes `pod_supervise::start::<table::Detail, _, _>`.
- `pod_proxy::blocking::Stream` and `pod_proxy::Stream` have the new
  variant `Tls` (T-1431), and `ProxyKind` has `Https`. No enum is
  `non_exhaustive`. podvm: the `match` of
  `crates/podvm-ssh/src/transport/egress.rs` has no wildcard arm: add
  `blocking::Stream::Tls(_)` (refuse it as `Exec`, or take it as a stream
  with its read limit on the inner socket). podnet, podssh and podrunner
  do not match these enums.
- `pod_egress::wisp::Connect` has the new public field `login:
  Option<Login>` (T-1527). `Connect` has no `Default`: podnet's literal in
  `up` of `src/networks/servers/wisp.rs` adds `login: None`.
  `wisp::answer` takes `(server, login)`; no consumer calls it. A refused
  credential of a Wisp server (reasons 0xc0 to 0xc2) is the stage `Relay`
  and the class `Refused`, not the stage `Origin`.
- `pod_job::UnitFields` has the new public field `limits:
  Option<UnitLimits>` (T-1529), and `pod_job::Status` has
  `no_tier_served_causes: Vec<NoTierCause>` (T-1550). Neither struct has
  `Default`. podrunner: the `UnitFields` literal of
  `crates/podrunner-slots/src/report.rs` adds `limits: None`; the `Status`
  literal of `crates/podrunner-slots/src/status.rs` adds
  `no_tier_served_causes: Vec::new()`. The schema ids stay `run-report.v1`
  and `status.v1` (section "Schemas").
- `pod_relay::grant::openssh_public` is removed (T-1473). podssh:
  `crates/podssh-cli/src/grants.rs` (its lines 79, 343 and 361):
  `grant::openssh_public(&k)` becomes `k.openssh()`
  (`pod_identity::PublicKey::openssh`, the same type).
- `pod_actions_store::Error` has the new variant `SelfUses { uses, fault }`
  (T-1542). The enum is not `non_exhaustive`. `with_fix` of podrunner's
  `crates/podrunner/src/run_local/actions.rs` has a wildcard arm, so it
  builds; its arm `(Error::Uses { uses }, _) if is_self(uses)` no longer
  matches a `$/PATH` of the store: match `Error::SelfUses`.
- `pod_actions_store`: the owner and the name of an action match with no
  case (T-1541, call C980). A lock with two spellings of one reference
  fails to read (`LineFault::Again`). `workflow_uses` drops
  `Actions/Checkout@v4` too.
- `pod_acme::Acme` has the new public field `contacts: Vec<Contact>`
  (T-1505). Each field of `Acme` is public: a literal adds `contacts:
  Vec::new()`. No consumer builds `Acme` by its fields (podnet and podssh
  call `Acme::new`), so no build breaks.
- `pod_oci::Reference::parse` refuses a name of more than 255 characters,
  a tag of more than 128, a tag that starts with `.` or `-`, and a path
  component outside docker's grammar (`-a`, `a..b`), each `Class::Usage`
  (T-1426). `pod_guest::ext4::write_empty` refuses a size that is not a
  whole number of 4 KiB blocks (T-1500).
- `pod_egress::shadowsocks`: a key with Outline's salt prefix is taken (it
  was refused in YAML and JSON, and the prefix of an `ss://` link was
  dropped), and the prefix goes first in each salt (T-1526).
- The error texts of the section "Error texts".

## Error texts

These lines change. A test that matches the old text gets the new one.

- `pod-enter`: "the read-only root of the plan: TEXT; the payload did not run"; a plan with a read-only root off the namespace rung names "the read-only root" in the refusal of a volume, a tmpfs or a fallback. A missing working directory with `WorkdirMade::NotMade`: "the working directory "/gone" for image "img" is not a directory in the image" (no clause "docker creates it").
- `pod-hostprobe`: with an emulator path, the version line and the list of accelerators end with " (PATH)"; "no emulator at PATH, so ...".
- `pod-proxy`: "an https:// proxy is on TCP alone: TLS checks the name of its host, and a Unix socket or a command has none; ..."; "https://HOST:PORT is reached over TLS, and this dial has no TLS context for a proxy"; "the proxy for TARGET is reached over TLS (https://), and this caller takes a plain TCP connection only". An unknown scheme names "http:// or https://".
- `pod-oci`: "the name has N characters, and the most is 255"; the tag and a component outside docker's grammar are named; the input in an error is cut to 64 characters. A failed ping: "HTTP 401: UNAUTHORIZED: ...".
- `pod-acme`: `the contact "TEXT": WHY`; "the account: the CA refuses the contact mailto:ADDR: invalidContact: DETAIL"; the line `acme.account` of a new account ends with ", contact mailto:ADDR".
- `pod-egress`: a Wisp dial in the backoff ends with "(no new connection to the Wisp server within N s)"; a Wisp login over `ws://` to a host that is not the loopback is `ConnectError::Config`; a `Display` of a Shadowsocks `Node` shows no password and no path.
- `pod-core`, `pod-unit`, `pod-link`: the words of the system with no " (os error N)"; `text::file_words` gives "no such file" or "the directory DIR does not exist".

## Exit codes

- No class changes its code. A refused Wisp credential is `Refused` (77) at the stage `Relay`. A refusal of `Reference::parse`, of `Contact::parse` and of `write_empty` is `Usage` (64). `check_layers` is `Protocol` for a wrong count and `Policy` past `MAX_LAYERS`. `EntryFailure` keeps the class `Unavailable` (69) of a failed start; its code (127, 126) is a typed cause (call C996).
