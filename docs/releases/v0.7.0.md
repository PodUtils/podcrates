# podcrates v0.7.0

The seventh release of podcrates: keep-alive connections in the HTTP
client of `pod-proxy`, and the cause of I/O of a `pod_core::Failure`.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-proxy` | the client keeps idle connections for each scheme, host, port, way out and trust (30 s, 4 for each key, 16 for each client) and gives one to the next request of the same key; a connection goes back only when its HTTP/1.1 answer was read to its end; a GET or HEAD that fails on a kept connection before any byte of the answer is tried once more; `Client::with_keep_alive(false)` turns it off; on by default (T-077) | podvm (its registry pulls), each client |
| `pod-core` | `Failure::io_cause()` gives the error of I/O of the chain of causes; `Class::NotFound` is the class of `ErrorKind::NotFound` (T-081) | podvm (its space and exec checks) |
| the others | no change | |

## How a consumer takes it

Each podcrates dependency names the tag `v0.7.0`.

## Breaking

- `pod_core::Class` has the variant `NotFound`, and `Class::of_io` gives it
  for `ErrorKind::NotFound` (before: `Unavailable`). A `match` with no `_`
  arm adds it; a check of "not found" as `Unavailable` changes.
- A request with keep-alive on sends no `Connection: close`; the request
  head of `https_get` is the same as before.

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (ruling Q1).
