# podcrates v0.37.0

The thirty-seventh release of podcrates. For podssh: a team's token with
a registration of `pod-warp`, and the API base that answered (T-480), so
the trial of `pod-warp` in `crates/podssh-warp` (T-413) builds on a tag.
For podvm: a fresh proc on the `/proc` of the image in the namespace
rung of `pod-enter` (T-491, PodUtils/podvm#296), and an entry that joins
the mount namespace of a running payload, for an exec (T-492,
PodUtils/podvm#297). For each consumer: the nightly builds the tests of
`pod-relay` on Windows again (T-488).

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-warp` | `Api::with_team(token)`: the token of a team goes as `CF-Access-Jwt-Assertion` on the `POST /reg` alone, and its `Debug` shows `Team(..)`; `Api::answered()` gives the base that gave the last answer under 500 (T-480) | podssh, podnet |
| `pod-enter` | the namespace rung mounts a fresh `proc` (`nosuid`, `nodev`, `noexec`) on the `/proc` of the image where that directory exists (`ns_proc_target`); a refused mount writes one line to the payload's standard error and the rung goes on (`ns_proc_refused`, `NS_PROC_STEP`) (T-491); `spawn_joined(root, plan, pidfd, err)` joins the mount namespace of a running payload with `setns(pidfd, CLONE_NEWNS)` and mounts nothing; a refused join writes `ns_join_fallback_line` and enters `spawn_namespace` (`NS_JOIN_STEP`) (T-492) | podvm |
| `pod-hostprobe` | `sys::setns`; `sys::MS_NOSUID`, `MS_NODEV`, `MS_NOEXEC` | podvm |
| `pod-relay` | a test only: the Unix half of a test of the reverse road runs on Unix alone, so the tests build on Windows (T-488) | none |

## How a consumer takes it

Each podcrates dependency names the tag `v0.37.0`.

- podssh: move the tag. The trial patch `adoption/podssh/pod-warp.patch`
  (T-413) names this tag; the COORD issue of the freeze of
  `crates/podssh-warp` follows the hand-off.
- podvm: move the tag. A container of the namespace rung gets a `/proc`
  where its image has the directory (your T-1758). For `podvm exec`, call
  `pod_enter::spawn_joined` with the pidfd of the payload from the record
  of `pod-supervise` (your T-1765); a refused join prints its line, and
  the exec runs in a namespace of its own.
- podnet: move the tag. The trial patch `adoption/podnet/pod-warp.patch`
  (T-412) names this tag; the COORD issue of the freeze of `src/warp/`
  follows the hand-off.
- podrunner: move the tag.

## Breaking

- None.

## Known defect

- `pod-relay`: the client of the HTTP road sends no `POST close` when the
  app drops its stream (T-478, open).
- `pod-netstack`: a stream dropped before its handshake ends finishes the
  handshake later (T-482, open).
- `pod-netstack`: the reactor gives one ACK for the segments of one poll
  (T-197, open).
- `pod-session`: a random failure of one test under load (T-204, open).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
`pod-link`, `pod-turn`, `pod-devtunnel`, `pod-warp` and `pod-netlab` are
not reserved on crates.io yet: the owner reserves them before a publish.
