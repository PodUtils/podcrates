# podcrates v0.79.0

The seventy-ninth release of podcrates. It carries, for the CI of githome
and podrunner, the verifier of `pod-release` for the bundles of Rekor v2
and the clients of a job through the TLS end of `pod-broker`; the
acceptance registry of `pod-todo` and its asset `acceptance.json`; and the
fixes of `main` for podnet (an error line names each cause once), for podvm
(the signals of the waiter, the `RUNPATH` of the loader family) and for
Windows.

## Error texts

These lines change (T-985 to T-987, PodUtils/podnet#658). A test that
matches the old text gets the new one.

- A request through a proxy that does not answer: `POST https://HOST/PATH: could not reach the proxy 127.0.0.1:P: could not connect to 127.0.0.1:P: Connection refused (os error 111)`. The request is named once.
- `pod-warp`, two bases that fail at one proxy: `the WARP API: each host failed: 2 hosts (https://api.one.example, https://api.two.example): could not reach the proxy 127.0.0.1:P: ...`. With one base: `the WARP API: POST https://HOST/PATH: ...`. With bases that fail in different ways: `the WARP API: each host failed: BASE: TEXT; ...`. The text `the WARP API at BASE (before: ...)` is removed. Each base that fails before the last gives a `tracing` line at the level info.
- `pod-ws` and `pod-proxy`: `could not connect to 127.0.0.1:1: Connection refused (os error 111)` and `could not resolve HOST: system resolver: ...`, with the target once.
- `pod-devtunnel`: `STEP: REQUEST: ...`, with the request once.
- `pod-services-watch`: the finding of a failed request is the chain of the failure, which names the request once.
- `pod-enter`, the waiter with no signalfd: `waiting without shutdown forwarding (WHY); a SIGHUP, SIGINT, SIGQUIT, SIGUSR1, SIGUSR2, SIGTERM, SIGALRM or SIGPWR to this process does not reach the payload`. A forward line names SIGQUIT, SIGUSR1, SIGUSR2, SIGALRM and SIGPWR by name.

## Schemas

- `acceptance.v1` (new): the acceptance of a release, `{"schema": 1, "asks": [{"ask": ID, "tests": [TEST, ...]}]}`, from `TODO/ACCEPTANCE.md` by `cargo todo acceptance --json` (T-105).

## The keys of `TODO/todo.toml`

- `defect_tests = "YYYY-MM-DD"` (T-979). This repository sets `2026-11-17`.
- `acceptance = "TODO/ACCEPTANCE.md"` (T-105). The file becomes a record file of `TODO/`.

## Breaking changes

- `pod_release::sigstore::Roots` has the fields `fulcio`, `logs` (`Vec<Log>`) and `tsa`; the field `rekor` is removed. `Roots::from_pem` takes `(fulcio, &[(name, key_pem)], tsa_pem)`. A caller that builds `Roots` by its fields gives `logs: vec![Log { name, key }]` and `tsa` (with an empty `tsa`, a bundle that holds a timestamp is refused; a bundle with Rekor's promise needs no timestamp). For a key that is not Ed25519 (Rekor v1), the log id stays the SHA-256 of the key's DER.
- `pod_todo::config::Config` has the fields `defect_tests` and `acceptance`: a caller that builds `Config` by its fields names them. `Config::default()` and `config::parse` give `None` for each.
- `pod_enter::PID_FORWARDED` holds SIGALRM and SIGPWR: the init of a PID namespace gives them to the payload. `Child::wait_forwarding` gives each signal of `WAIT_FORWARDED`, and does not give a SIGINT or a SIGQUIT that a terminal sent.
- `pod_enter::userland::loader_plan` puts the `RUNPATH` directories of the payload before the default directories of its library path.
- `pod_warp::api::Api::send`: when each base failed at one hop, the cause of the failure is that hop (its `DialError`), not the whole failure of the last base.
- The error texts of the section "Error texts".

No consumer matches with no wildcard an enum that changed: no enum of a public API changed.

## Release assets

- New: `acceptance.json` (`schemas/acceptance.v1.schema.json`), in `SHA256SUMS`, and named by the field `acceptance` of `release-index.json`. `release.yml` writes it with `cargo todo acceptance --json`.

- New step of `ci.yml`: "pod-broker with the clients of a job" (`scripts/ci/broker-clients-tests.sh`, Node.js and `requests` pinned by SHA-256; `nodejs.org` is a host of `scripts/check-workflows.py`).

- New fixtures: the Rekor v2 bundles of sigstore-conformance with their licence (`crates/pod-release/tests/fixtures/sigstore/`).
- The Windows fixes T-934, T-935 and T-990 have their tests on each system; their proof on `windows-2025` and `windows-11-arm` is the next run of `nightly.yml`.
- The step "Test pod-gsr (Windows ARM64, open defect)" of `nightly.yml` runs after a failed step.
- `fuzz/Cargo.lock` names `socket2` as a dependency of `pod-quic`.
- The rustdoc of `pod_warp::api::Api::send` links no private item, so the step `cargo doc` of `ci.yml` (`-D warnings`) passes.

## How a consumer takes it

Each podcrates dependency names the tag `v0.79.0`; `issue-sync.yml@v0.79.0` takes `podcrates_ref: v0.79.0`.

- podrunner: pin the new SHA-256 of the asset `pod-release-x86_64-unknown-linux-musl`. It verifies a bundle of Rekor v2 and a bundle with an RFC 3161 timestamp. For G-35, give each client of a job the variable that the README of `pod-broker` names for it; Node.js needs `--use-env-proxy` or `NODE_USE_ENV_PROXY=1`. Set the keys `defect_tests` and `acceptance` of `TODO/todo.toml` when the record is ready for them.
- podvm: no change of podvm's code is necessary. The waiter and the init give SIGQUIT, SIGUSR1, SIGUSR2, SIGALRM and SIGPWR to the payload (#608), and the library path of the loader family names the `RUNPATH` directories of the image (#603). A test of podvm that reads the warning line of the waiter gets the new text.
- podnet: the error lines of #658 change (section "Error texts"). The key `defect_tests` (#657) is in `pod-todo`: set it in `TODO/todo.toml`. On Windows, an exec proxy runs `cmd.exe`, and the QUIC leg of `pod-cloudflare` reaches an edge of IPv4.
- podssh: `tests/update_support/mod.rs` builds `Roots` by its fields: give `logs: vec![pod_release::sigstore::Log { name, key: rekor.spki() }]` and `tsa: Vec::new()`. `podssh update` verifies a release that cosign signs with Rekor v2.
