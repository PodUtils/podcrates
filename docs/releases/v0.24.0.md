# podcrates v0.24.0

The twenty-fourth release of podcrates. For podvm: `pod-guest` reads the
squashfs modloop of a guest kernel and gives the module set of a list of
names with their dependencies (PodUtils/podvm#260), and `pod-services`
holds the three gaps of podvm's inventory (PodUtils/podvm#263).

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-guest` | `squashfs`: a read-only reader of squashfs 4.0 over a `Read + Seek` (the superblock, the compressor options, the tables, stored, sparse and xz blocks; each offset and size checked, a ceiling before each allocation, a typed `squashfs::Fault`). `modloop::modules(reader, kernel_release, names) -> ModuleSet`: each name and each dependency of `modules.dep`, each once, in load order, with the `modules.dep` of the set; a name of `modules.builtin` needs no file; an unknown name is `modloop::Fault::Unknown`. The xz decoder is `xz4rust` with the x86 BCJ filter, in Rust (call C58). Fuzz target `squashfs_image`; a daily live read of Alpine 3.22's `modloop-virt` in `live.yml` (T-206) | podvm |
| `pod-services` | `gcr-registry` (`gcr.io`, the pin of `distroless/static-debian12`); `mirror-gcr-registry` (`mirror.gcr.io`, Google's mirror of Docker Hub, with the pin of `guest-userland`; call C59); the facts `kernel-release`, `module-failover-sha256`, `module-net-failover-sha256` and `module-virtio-net-sha256` of `alpine-netboot` (the NIC modules in `boot/initramfs-virt` of 3.22.6) (T-211) | podvm |

## Checks

- The dev profile of the fuzz workspace optimizes the crates under test:
  the stable test of the fuzz targets takes seconds, not minutes (T-206).
- `pod-broker`: the test `a_socket_path_that_is_another_file_is_refused`
  makes its socket in a short directory, so it passes where `TMPDIR` is
  long (T-206).

## How a consumer takes it

Each podcrates dependency names the tag `v0.24.0`.

- podvm reads the module set of its guest with `pod_guest::modloop::modules`
  (PodUtils/podvm@T-1662), and reads `gcr-registry`,
  `mirror-gcr-registry` and the module sums of `alpine-netboot` from
  `pod-services` (PodUtils/podvm@T-1679); its list of reported hosts gets
  empty.
- podnet, podssh and podrunner move the tag; no API of theirs changes.

## Breaking

- None.

## Known defect

- `pod-confine`: the Landlock scopes and UDP stay open to a confined
  payload (T-209, open).
- `pod-session`: `a_session_moves_while_both_ends_send_at_full_speed` lost
  its link one time in a run of the workspace's tests (T-204, open).
- `pod-netstack`: the reactor of `NetStack` gives one ACK for the segments
  that one poll takes (T-197, open).
- `pod-gsr` on Windows ARM64: a test process ends with
  `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
