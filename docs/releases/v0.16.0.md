# podcrates v0.16.0

The sixteenth release of podcrates: the kill of the tree of a payload in
`pod-supervise` for podvm and podrunner; a listener of `pod-broker` bound
to one job for podrunner; the dial state of a held `connect` and the
packets of the hold of a SYN in `pod-hold` for podnet, podvm and podrunner;
private modes of the state of `pod-supervise`; four dead public nodes out
of `pod-services`.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-supervise` | The launcher is the child subreaper of the payload's tree: at the end of the payload it kills each descendant (`Settings::kill_tree`, default true), also one that called `setsid` or ignores SIGTERM. `set_wall(&s, want, ms)`: a wall bound of a run. `Container::end` (`end::End`): the reason (`exit`, `signal`, `wall`), `run_ms`, the use of the tree (`user_ms`, `system_ms`, `max_rss_kib`) and `residual_processes` (a number, or `"unknown"`, never 0 when not known). The record holds the end before a waiter gets the code. No `RLIMIT_FSIZE` is set (T-162) | podvm (PodUtils/podvm@T-1655), podrunner (PodUtils/podrunner#23) |
| `pod-supervise` | The table and each log are 0600 from their first byte, each container directory and `staging/` 0700, under any umask: the table holds the environment of each record (T-175, PodUtils/podvm#244) | podvm (PodUtils/podvm@T-1715), podrunner |
| `pod-hostprobe` | `sys::set_child_subreaper`, `sys::reap_any`, `sys::rusage_children` and `Usage`, `sys::umask`, `ECHILD`, `PR_SET_CHILD_SUBREAPER` (T-162, T-175) | `pod-supervise` |
| `pod-broker` | `Broker::serve_unix_job(job, listener)`, `serve_tcp_job`, `handle_bound`: a listener of one job, with no token in the unit; a `Proxy-Authorization` of another job gets 407; a reload keeps the listener, a drop or the TTL ends it (`broker.listener.end`) (T-160) | podrunner (PodUtils/podrunner#24), podvm (`--net broker`) |

## How a consumer takes it

Each podcrates dependency names the tag `v0.16.0`. No adoption patch: each
change is an addition of API, or the breaking changes below.

## Breaking

- `pod_supervise::table::Container` has the fields `wall_ms` and `end`, and
  `pod_supervise::Settings` has `kill_tree` and `proc`: a struct literal
  names them (`Settings::new` sets them).
- `pod-supervise` kills the descendants of a payload at its end, as the end
  of PID 1 of a namespace does. `Settings::kill_tree = false` keeps the old
  behaviour and counts them.
- `pod-services`: the four service ids above are gone.

## Known defect

- `pod-gsr` on Windows ARM64: a test process ends with
  `STATUS_ACCESS_VIOLATION` (T-131, open).
- Three tests of `pod-enter` fail under qemu-user only (T-149, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
