# podcrates v0.77.0

The seventy-seventh release of podcrates. It carries the new crate
`pod-release` (a signed release index, its verifier and the self-update of
a binary, from podnet and podssh), the PAX headers of a layer read with a
bound and by length for podrunner and podvm, a cooked session with no
prompt for podssh, and the second public Nostr relay of the pairing.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-release` (new) | The release index `release-index.json` (`schemas/release-index.v1.schema.json`), written by `scripts/release-index.py` (call C793). The verifier of a release: the keyless cosign bundle of `SHA256SUMS` (Rekor's signed entry timestamp, the chain to Fulcio at the time of the entry, the identity of the caller as `Identity { uri, issuer }` or `Identity::github(repo, workflow, tag)`), then each file and the index against `SHA256SUMS`. The self-update of a running binary: `version`, `trial`, `replace`, `keep` (`rollback`, `fallback`), and with the feature `fetch` the fetch of a release through the caller's `pod_proxy::Client` (`update::newest`, `plan`, `signed`, `binary`, `install`). podssh's copy is the base, with podnet's checks (call C794) (T-104, T-880) | podnet, podssh |
| `pod-extract` | `pax::Framed` reads the stream of a layer before the `tar` reader: a PAX header past 1 MiB and a GNU long name or long link past 4096 bytes are refused before their data, with the cause `Refusal::Member`; each PAX record is read by its length, so an attribute value with a newline byte is set, and a `path` or a `linkpath` with one is read from the record (T-961) | podrunner, podvm |
| `pod-term` | `Discipline::without_prompt` and `Session::without_prompt`: a cooked session with no prompt, for a command that a server runs with no pty; echo, the editing and the signals stay; `Discipline::prompt` gives the prompt that the caller draws first (T-960, PodUtils/podssh#326) | podssh |
| `pod-wormhole` | An other end that says nothing at a Nostr relay is named with the counts of this end: the events sent, accepted, and passed of the other key (`Place::tally`) (T-963) | podssh, podnet |
| `pod-services` | `noslol-nostr` (`wss://nos.lol/`) takes rank 2 of the kind `nostr-relay`; `offchain-nostr` leaves the catalog: it refuses a key outside its web of trust, and each pairing draws new keys (call C796, T-963) | podssh, podnet |
| `pod-testkit` | The feature `schema` (`schema::compiled`, `schema::holds`): a file of `schemas/` against its types, and a validator of JSON Schema 2020-12 | each |

## Schemas

- New: `release-index.v1` (T-104).

## Breaking changes

- `pod_extract::xattr::read` takes the records of the entry (`&member.xattrs` of `pax::Side::next`) in place of the `tar` entry.
- `pod_extract::safety::Refusal` has the variant `Member(String)`: a `match` with no wildcard needs its arm.

## Tests and checks

- New plants: `extract-t961-pax-header-unbounded`, `release-no-signature`, `release-any-identity`.
- `release.yml` writes `release-index.json` before `SHA256SUMS`, which holds its line: the one signature of `SHA256SUMS` signs the index too.
- The fuzz run pins `nightly-2026-11-18` (T-968).
- `deny.toml` allows MIT-0 for `borrow-or-share` alone (call C795).
- `live.yml` runs both pairing tests of its step and fails at its end (T-963).

## How a consumer takes it

Each podcrates dependency names the tag `v0.77.0`; `issue-sync.yml@v0.77.0` takes `podcrates_ref: v0.77.0`.

- podrunner and podvm: a match on `Refusal` gets the arm `Member`; a layer with a binary attribute value extracts it.
- podssh: run an exec'd command on `Session::without_prompt` (#326). The take of `pod-release` is T-966: the Done section of T-880 lists each file that goes.
- podnet: the tag; the take of `pod-release` is T-966, as for podssh.
