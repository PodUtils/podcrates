# podcrates v0.23.0

The twenty-third release of podcrates. For podvm: `pod-confine`, the
confinement of a payload with no privilege (Landlock, a seccomp deny filter
and `no_new_privs` from one spec), and `Plan.confine` of `pod-enter`; a
layer whose root directory entry has an empty name applies.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-confine` | new (new code, call C57): `Spec` with the paths and their `Access` (`READ`, `WRITE`, `EXECUTE`), the TCP ports to connect and to bind, and a `Deny` list (`Deny::defaults()`: the namespace calls, the mount calls, `ptrace` and `process_vm_*`, the key calls, `bpf`, `perf_event_open`, `kexec_*`, the module calls, `*_handle_at`; `clone3` gets `ENOSYS`); `check()` and `probe()` read the Landlock ABI and apply a minimal ruleset in a disposable child; `Spec::compile` (host paths) and `Spec::compile_in` (guest paths, `openat2(RESOLVE_IN_ROOT)`) open each path before the fork; `apply` in the child sets `no_new_privs`, the ruleset and seccomp mode 2 with no allocation. A kernel with no Landlock and an ABI under 3 are refused; TCP rules need ABI 4 (T-108) | podvm |
| `pod-enter` | `Plan.confine: Option<pod_confine::Spec>`: applied in the child after the limits and `no_new_privs`, as the last step before the exec (step 15, with the path or the port of the failed rule). Fixed: a descriptor of `Fds.pass` onto the number of the readiness pipe or of the root; a descriptor passed onto its own number kept its close-on-exec flag (T-108) | podvm |
| `pod-extract` | `safety::is_root_entry`: a directory entry with an empty name is the root of the layer, as `./` is; `apply_layer` skips it. An empty name of another type stays refused. The layers of `public.ecr.aws/lambda/provided:al2023` apply (T-208, PodUtils/podvm#261) | podvm |
| `pod-hostprobe` | the Landlock calls, `connect`, the numbers of the deny list, and the one table of the audit arch (`sys/landlock.rs`, `sys/seccomp.rs`) (T-108) | each |
| `pod-hold` | reads the audit arch table of `pod-hostprobe` in place of its own; no change of the API (T-108) | podnet |

## Checks

- `scripts/plant-each.sh --apply` checks that each planted defect applies
  to the tree, in less than one second; `check.sh` and the lint job of
  `ci.yml` run it (T-210).

## How a consumer takes it

Each podcrates dependency names the tag `v0.23.0`.

- podvm sets `Plan.confine` from its profiles (PodUtils/podvm@T-1658):
  guest paths on each rung with a chroot, host paths on the entry with no
  chroot. `pod_confine::probe()` tells a host with no Landlock before a
  run. Its OCI pull of `public.ecr.aws/lambda/provided:al2023` needs no
  change.
- podnet, podssh and podrunner move the tag; a struct literal of
  `pod_enter::Plan` names `confine`.

## Breaking

- `pod_enter::Plan` has the field `confine`: a struct literal names it.
- `pod_enter`: a pass of `Fds.pass` onto the root or the memfd is refused
  before the fork.

## Known defect

- `pod-confine`: the Landlock scopes (signals, abstract Unix sockets) and
  UDP stay open to a confined payload (T-209, open).
- `pod-session`: `a_session_moves_while_both_ends_send_at_full_speed` lost
  its link one time in a run of the workspace's tests (T-204, open).
- `pod-netstack`: the reactor of `NetStack` gives one ACK for the segments
  that one poll takes (T-197, open).
- `pod-gsr` on Windows ARM64: a test process ends with
  `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
