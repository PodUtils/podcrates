# podcrates v0.73.0

The seventy-third release of podcrates. It carries the asks of podrunner
first (the ruling "podrunner first"): the three fields of `status.v1`
that podrunner needs to take `pod_job::Status`, a fake GitHub and a fake
of githome's source as static programs for the CI of podrunner and
githome, and the client's line of each wait of `pod-session` for the gate
of podssh.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-job` | `SourceStatus::draining`, `Status::max_units` and `Status::units`, each optional with a default; `schemas/status.v1` keeps its id, with three rows `added` in `schemas/CHANGES.md` (T-947, PodUtils/podrunner#305) | podrunner, githome |
| `pod-testkit` | The feature `github` and the program `pod-fake-github`: a fake GitHub on one loopback port, with the App JWT and the installation token, `generate-jitconfig`, the broker of a runner for a job of `run:` steps, the `workflow_job` webhooks signed with `X-Hub-Signature-256`, and a control API under `/_fake/` (T-921, GitHub #223 G-30, call C785) | podrunner, githome |
| `pod-testkit` | The feature `githome` and the program `pod-fake-githome`: `serve` keeps the jobs and a control API under `/_fake/`; `source` is a source program of kind `program` that speaks `pod_job::source` on stdin and stdout, as githome's source does, and finds `serve` by `--server` or `POD_FAKE_GITHOME`. It passes the steps of podrunner's `source-conformance` (T-948, PodUtils/podrunner#306, githome's G-38, call C786) | podrunner |
| `pod-session` | `resume::Note::Stall { words }`: the client says each wait of its link that holds 20 s (the application took no byte while bytes wait for it; the reader of the application waits for room or for the writer of the link), with the offsets each way. The far end's `session.stall` line ends with the bytes received and the bytes not yet written to the target, and a target that takes no byte for 20 s gets its own line (T-945, PodUtils/podssh#283) | podssh, podnet |

## Release assets

Each release attaches `pod-fake-github-TARGET` and `pod-fake-githome-TARGET`
for `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl`, with a
line of each in the signed `SHA256SUMS`.

## Tests and checks

- New plants: `session-t945-wait-unsaid`, `testkit-github-assignment-ignored`, `testkit-github-jwt-life-unbounded`, `status-units-required`, `testkit-githome-claimed-twice`, `testkit-githome-host-facts-ignored`.
- The `static` job of `ci.yml` builds `pod-fake-github` and `pod-fake-githome` on each Linux target of zig, with `check-static.sh` and `check-strings.py`.

## How a consumer takes it

Each podcrates dependency names the tag `v0.73.0`; `issue-sync.yml@v0.73.0` takes `podcrates_ref: v0.73.0`.

- podrunner: take `pod_job::Status` in place of your own, and remove your `schemas/status.v1.json` (your T-508). Pin `pod-fake-githome` by its line of `SHA256SUMS` for your T-509: run `pod-fake-githome serve`, queue two jobs (one run of `source-conformance` takes one job), and give `[[source]] kind = "program"` the command `pod-fake-githome source` with `POD_FAKE_GITHOME` set. `pod-fake-github` can replace `podrunner-broker-fake` for a job of `run:` steps, and it is the fake GitHub of githome's G-40.
- podssh: show `Note::Stall` at `-v`; a match on `Note` with no catch-all arm needs a new arm.
- podnet and podvm: the tag only.
