# podcrates v0.18.0

The eighteenth release of podcrates. For podrunner: the names mode of
`pod-broker` for an upstream proxy that takes names only, with its canary
and the flag of an allow rule under an open suffix; one version rule for
each schema of `schemas/` (the field `schema`); the `policy` of a job offer
of `pod-job` is a `broker-policy.v1` policy. For podssh: three more
tunnel services in `pod-services` and `Rewound::new` in `pod-session`.

## Crates

## How a consumer takes it

Each podcrates dependency names the tag `v0.18.0`. A writer of a broker
policy writes `"schema": 1` in place of `"version": 1`. A reader of a log
line of `log.v1` reads the key `schema` first. A validator of
`job-offer.v1` takes `broker-policy.v1.schema.json` as a resource too.

## Breaking

- `pod-broker`: a policy with the key `version` is refused (an unknown
  field); `Policy::version` is `Policy::schema`, and `policy::VERSION` is
  `policy::SCHEMA`.
- `pod-broker`: `audit::Line` has the field `schema`; `Settings` has
  `names_upstream` and `canary`, and `JobInfo` has `flagged`: a struct
  literal names them (`..Default::default()` for `Settings`).
- `schemas/log.v1.schema.json` requires `schema`: a line with no `schema`
  is refused.
- `pod-job`: an offer with a `policy` that is not empty and not a
  `broker-policy.v1` policy is refused.

## Known defect

- `pod-gsr` on Windows ARM64: a test process ends with
  `STATUS_ACCESS_VIOLATION` (T-131, open).
- Three tests of `pod-enter` fail under qemu-user only (T-149, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
