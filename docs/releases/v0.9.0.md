# podcrates v0.9.0

The ninth release of podcrates: `pod-guest` (a disposable QEMU guest) and
`pod-enter` (the entry of a payload), both from podvm; the SOCKS5 datagram
path of `pod-proxy`; the 32-bit ids of `pod-hostprobe`; a daily live
workflow and a wider static probe.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-guest` | new: a disposable QEMU guest: `Plan`, `Accel`, `accel_for`, the command lines, `run`, `provision`, `stop`, the per-run directory, the FAT16 mailbox, the agents, QMP, the bounded store of a base image (T-061; call C36). A malformed chain that the guest wrote reads as no file, not a panic | podvm (`adoption/podvm/pod-guest.patch`) |
| `pod-enter` | new: the entry of a payload: `Names`, `Plan`, `spawn`, `run`, the ladder, the userland and namespace entries, `abi`, `binfmt`, `device`, `fuse`, `memfd` with its probe, `stage`; `Error::payload_code` and `code_or` (T-059; call C37). The ELF reader checks each offset and bounds the count of section headers | podvm (`adoption/podvm/pod-enter.patch`) |
| `pod-proxy` | `pod_proxy::udp`: the SOCKS5 datagram path (UDP ASSOCIATE, the command 0x83 "UDP in stream", the frames and the datagram header); a reply 0x07 is `DialError::UdpRefused` (T-083, #21; call C23) | podnet (`pod-warp`, T-028) |
| `pod-hostprobe` | on i686 and arm, the id calls use the 32-bit forms (`getuid32`, `getgid32`, `setuid32`, `setgid32`, `getgroups32`, `setgroups32`, `chown32`, `lchown32`): an id above 65535 reads whole (T-132). `O_DIRECTORY` and `O_NOFOLLOW` have the kernel values of arm, aarch64 and powerpc (T-134) | podvm (its i686 and ARM builds), `pod-enter` |
| `pod-testkit` | `need_root!` (T-059) | each crate's tests |
| the others | no change | |

Checks: `live.yml` runs the live tests each day (T-092, #30); the static
probe links `pod-proxy/blocking`, and `static-probe-lean` builds `pod-core`
and `pod-tls` with no tokio (T-095, #33); `scripts/check-design-paths.py`
holds `docs/design.md` and the README to the tree (T-093, T-094).

## How a consumer takes it

Each podcrates dependency names the tag `v0.9.0`. podvm applies, in this
order, `adoption/podvm/pod-supervise.patch` (if not taken with v0.8.0),
`pod-guest.patch` and `pod-enter.patch`, and runs the lines of each
`.run`. `pod-enter.patch` is made on podvm `6cd3442`; the two others on
`27ae993`: merge their tag lines and the `pod-*` rows of
`docs/runtime-state.md`.

## Breaking

- None in the crates that a consumer takes now.

## Known defect

- `pod-gsr` on Windows ARM64: a test process ends with
  `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
