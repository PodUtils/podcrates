# podcrates v0.5.0

The fifth release of podcrates: the fixes that the trials of podvm found
in the blocking face, a streamed body for the HTTP client, and two tests
that failed on macOS and Windows.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-proxy` | `Client::send_streamed` and `blocking::Client::send_streamed`: the head of an answer and a body that the caller reads as it comes (`AsyncRead`, `Read`), with Content-Length, chunked coding and read-to-close, a body cut short as `UnexpectedEof`, and a limit for each wait for body bytes (`Request::body_idle`, 30 s by default); `send` is the same path with its cap (T-069) | podvm (its registry and image pulls) |
| `pod-proxy` | the dial bounds each call of the resolver by its deadline: a resolver that did not keep to it held a dial of 200 ms for 30 s (T-070) | podssh, podnet, podvm |
| `pod-proxy` | the runtime of the blocking face shuts down in the background when its last holder drops (T-070); `blocking::Stream::set_timeouts` holds for a proxy at a command too (T-071) | podvm |
| `pod-tls` | an empty `Words::replace_roots` means no place that replaces the roots: the hint of an unknown issuer names only the place that adds to them (T-068) | podvm |
| `pod-dns`, `pod-proxy` | the tests of a refused port and of a tool's proxy file pass on macOS and Windows (T-067) | |
| the others | no change | |

## How a consumer takes it

Each podcrates dependency of a consumer names the tag `v0.5.0`. No API of
v0.4.0 changes: the move of the tag is the take. podvm sets
`replace_roots` to an empty text and `add_roots` to its host bundle.

## Breaking

- `pod_proxy::client::Request` has the field `body_idle`; a caller that
  builds a `Request` with a struct literal adds it.

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (ruling Q1).
