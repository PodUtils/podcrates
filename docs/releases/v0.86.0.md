# podcrates v0.86.0

The eighty-sixth release of podcrates. It carries each change of `main`
after `v0.85.0`. It has no new crate. For podrunner and podvm, it carries a
required tmpfs with a byte limit on the namespace rung of `pod-enter`
(PodUtils/podvm#667, for ask 5 of PodUtils/podrunner#296). For podnet, it
carries the asks PodUtils/podnet#753 to #756, #758 and #776: the line of a
name that does not resolve (`pod-dns`), the exec proxy (`pod-proxy`), the
limits of the edge discovery and a capture sink of the HTTP exchanges
(`pod-cloudflare`), the largest move under the cap of a relay
(`pod-session`) and the error of the loopback bind (`pod-link`). For podssh,
it carries the asks PodUtils/podssh#359 to #363 and #367: `pod-ws`,
`pod-quic`, `pod-relay`, `pod-warp`, `pod-core`, `pod-e2e`, `pod-identity`,
`pod-tls`, `pod-session`, `pod-release` and `pod-manual`. It also carries
the Dependabot updates of 2026-11-26 and a resolver setting of the lock.

## Breaking changes

A consumer reads this section first. Each item gives the fix.

- `pod_enter::Plan` has the new public field `tmpfs: Vec<TmpfsMount>`
  (T-1389). `Plan` is not `non_exhaustive` and has no `Default`: each struct
  literal of `Plan` adds `tmpfs: Vec::new()`. A literal with `..plan` builds.
  `TmpfsMount { guest: String, bytes: NonZeroU64 }` is new
  (`pod_enter::TmpfsMount`).
- `pod_proxy::DialError` has the new variant `ProxyExited { word, status,
  said }` (T-1393). The enum is not `non_exhaustive`: an exhaustive `match`
  adds an arm. Each `match` of a consumer has a wildcard arm (podnet
  `crates/podnet-core/src/connect.rs`; podssh `serve/egress.rs`,
  `doctor/samples.rs`, `pipe/remote.rs`, `via/reach.rs` and the `reach.rs`
  of each road), so no consumer build breaks.
- `pod_ws::ConnectError` has the new variant `Ended(String)` (T-1396). The
  enum is not `non_exhaustive`. Each `match` of podssh and podnet has a
  wildcard arm; podvm and podrunner do not name the enum. No consumer build
  breaks.
- `pod_e2e::Error` has the new variant `Target(std::io::Error)` (T-1403).
  The enum is not `non_exhaustive`: an exhaustive `match` adds an arm.
  podssh: `judged` in `crates/podssh-cli/src/channel.rs` matches each
  variant, so it does not build until it has an arm for `Target(_)`.
  `Error::Target` has the class `Unavailable` (exit code 69) for each kind
  of the error of I/O. The node's carry gives it for a failure of its
  target; the operator's carry keeps `Error::Io`.
- `pod_e2e::ends::Redeem` gives a `Redemption { credential, result }`, not
  a `Result<String, String>` (T-1408). Wrap a result in
  `Redemption::grant(..)` or `Redemption::bearer(..)`. podssh: the closure
  of `door` in `crates/podssh-cli/src/grants.rs` (the arm of a bearer takes
  `Redemption::bearer`, the arm of a grant `Redemption::grant`) and the
  closure of `node.redeem` in
  `crates/podssh-relay/tests/reverse_exit_caller.rs`. A refused bearer
  gives the operator `ends::BEARER_REFUSED`, not `ends::GRANT_REFUSED`.
  `GRANT_REFUSED` stays in `ends`.
- `pod_relay::pair::PairError::Forbidden` is `Forbidden { detail, once }`;
  it was a unit variant (T-1407). The new variant `NotMade { detail }` is a
  `403` of `/v1/pair` (`pair::create`, `once::create_with`,
  `once::create_by`): before, that `403` was `Forbidden`. The enum is not
  `non_exhaustive`. podssh: write `PairError::Forbidden { .. }` in each
  pattern: `crates/podssh-cli/src/pairs.rs` (`refusal` twice, `made_refusal`
  and the `match` of line 219), `relay_halt.rs`, `relay_renew.rs`,
  `node_expiry.rs`, `node_rotate.rs` (two), `relay_conform_reverse.rs` and
  `relay_cmd.rs`. Give the fields where podssh makes the value:
  `PairError::Forbidden { detail: String::new(), once: false }` in the test
  `a_refused_new_pair_is_not_a_stopped_one` of `pairs.rs` and three times in
  `crates/podssh-cli/tests/node_months.rs`. `made_refusal` gets a
  `Forbidden` no more for a new pair: match `NotMade`. In `refusal`, the
  wildcard gives `NotMade` the code 69; give it the code of `Forbidden`
  (the class of both is `Refused`, 77).
- `pod_relay::pair::Pair` and `OperatorPart` have the new public field
  `once: bool` (T-1407). Each struct has a private field, so no consumer
  builds one by its fields, and no build breaks. A file of a pair or of the
  operator's part keeps `"once": true`; a file with no mark reads `false`.
  An older reader ignores the key.
- `pod_cloudflare::Host` has the new public field `capture:
  Option<Arc<dyn capture::Capture>>` (T-1404). `Host` is not
  `non_exhaustive`: a struct literal adds `capture: None`. `Host::new` sets
  `None`. podnet builds its `Host` with `Host::new` (`base_host` of
  `src/tunnel.rs`), so it builds.
- `pod_manual::pager::run_program` gives `io::Result<Paged>`, not
  `io::Result<()>` (T-1412). No consumer calls it: podssh re-exports it in
  `crates/podssh-cli/src/pager.rs`, and that builds.
- `pod_release::update::Source` has the new public field `former:
  Vec<Former>` (T-1411). `Source` is not `non_exhaustive`: a struct literal
  adds `former: Vec::new()`. podssh builds it with `Source::github` and with
  `..Source::github(..)` (`crates/podssh-cli/tests/update.rs`), so it builds.
  podnet, podvm and podrunner build no `Source`.
- `pod_session`: a far end that closes the link before its first byte is
  "the far end closed the link before it said anything", not "the far end
  said nothing within 30 s" (T-1410), in `race`, `in_turn` and
  `each_timed`.
- `pod_identity`: `KeyName::parse` and `Allowlist::parse_with` read
  OpenSSH's line `ssh-ed25519 BASE64 [comment]` (T-1406). A line that was a
  bad line is now a key. `Allowlist::reaches_target` and
  `allow::reaches_target` refuse a key whose lines give `routes=` alone for
  the target with no route; `admits` does not change. The refusals of
  `allow::admits`, `allow::grants` and `allow::reaches_target` add the bad
  lines of the list.
- `pod_cloudflare`: the answer to a chunked request (no upgrade) is framed
  as the answer to each other request (T-1404). Before, the visitor got the
  raw bytes of the origin, with the size lines of a chunked answer.
- `pod_core::lock::FileLock` unlocks the file at its drop, before the close
  (T-1401). A copy of the descriptor in a child (a fork before its exec)
  does not keep the lock after the drop.
- `pod_core::files`: a create that gives `PermissionDenied` at a name where
  a file or a directory is takes a new name, as for `AlreadyExists`
  (T-1444). It acts on Windows, where a create at the name of a directory
  gives "Access is denied". `create_private` on Windows gives `Ok(false)`
  there, as on Unix.
- `pod_proxy`: the stderr of the command of an exec proxy goes to a pipe,
  not to the stderr of the process (T-1393). `ChildIo::stderr_tail` gives
  its last `STDERR_KEPT` (512) bytes. A command that exits 126 or 127 (9009
  on Windows) is held by its command line for `EXEC_HOLD` (10 s): each dial
  in the hold gives the same failure and starts no process.
  `Proxy::secret_parts` of an exec spec keeps the word of the program that
  the label shows readable.
- The error texts of the sections below.

## Error texts

These lines change. A test that matches the old text gets the new one.

- `pod-dns`: "could not resolve HOST: system resolver: CAUSE; DNS over HTTPS: 8 resolvers failed: 4 with CAUSE; 4 with CAUSE". For example: "could not resolve nothing.invalid: system resolver: Name does not resolve; DNS over HTTPS: 8 resolvers failed: 4 with a certificate that no trusted CA signed; 4 with Address family not supported by protocol". The one-group forms ("each of N resolvers failed: CAUSE", "ADDRESS: CAUSE", "CAUSE") stay. A cause that does not fit loses whole parts: what follows its first `; `, then its middle parts, then its head, then all but its class (`TLS`).
- `pod-proxy`: "the proxy command WORD exited 127 (not found) before it answered: LINE"; the status is "126 (cannot run)", "127 (not found)", "9009 (not found)" on Windows, "by signal N", or the code; with no word, "the proxy command exited ...".
- `pod-cloudflare`: the event `edge.discovery`: "the DNS of the edge took T s on WAY" (info), "the DNS of the edge waited T s on WAY, which gave no address; the client takes NEXT" or "the DNS of the edge waited T s (the limit of N s) on WAY; CAUSE; the client takes NEXT" (warn). After such an event, the line of the static list says "SOURCE: the line before gives the cause".
- `pod-session`: "the far end closed the link before it said anything"; "the far end said nothing within 30 s" stays for a silent far end.
- `pod-ws`: `ConnectError::Ended` is its words alone.
- `pod-e2e`: "the stream of the node's target failed, not the stream under the channel: ERROR" in the node's event `e2e.ended`. The node: "refused a grant of the operator key KEY: WHY" (it was "refused the grant of the operator key KEY: WHY") or "refused a bearer of the operator key KEY: WHY"; "came in, by a bearer" or "came in, by a grant". `BEARER_REFUSED`: "this bearer does not let this key in: it was used already, its 30 s passed, the node does not take its signer for this, or it is not for this key or this channel; the node's log says which".
- `pod-relay`: "the relay refused the token (403: WORDS): the pair is stopped or has expired" (it was "the relay refused the token (403 reverse: forbidden): ..."); with `once`: "the relay refused the token (403: WORDS): the pair's connect token is for one upgrade, and that upgrade is used; or the pair is stopped or has expired"; with no words, "(403)". "the relay refused to make a pair (403: WORDS): a relay that makes pairs for the keys of a list alone refuses each other key". A label: "the label is empty", "the label is longer than 128 characters" (it was "the label the pair name is empty"). "the mint gave no answer (reset: Connection reset by peer): a hop may cut cleartext". "PATH: No such file or directory" for a grant file (it was "PATH: No such file or directory (os error 2)"), and the same for the other lines of the section "Crates". The QUIC road: "system resolver: CAUSE" (it was "system resolver").
- `pod-quic`: "no address answered over QUIC: ADDRESS: CHAIN; ..."; a failed socket "no UDP socket for QUIC: CAUSE".
- `pod-tls`: each refused certificate in words, for example "invalid peer certificate: a certificate that no trusted CA signed" (it was "invalid peer certificate: UnknownIssuer") and "the certificate of a CA, served as the server's own: the server must serve a certificate that its CA signed" (it was `Other(OtherError(CaUsedAsEndEntity))`). "CA bundle /x: No such file or directory" (it was "CA bundle /x: /x: No such file or directory (os error 2)"). "VALUE cannot be read: WORDS" and "reading the file: WORDS" with no ` (os error N)`.
- `pod-link`: "TCP sockets on the loopback: 127.0.0.1: WORDS; ::1: no IPv6 on this host" (it was "TCP sockets on the loopback: ERROR OF THE SECOND BIND").
- `pod-identity`: a refused key adds "; line N is not a key: a line holds KEY_FORMS, then routes=A,B and a comment, both optional" when the list has a bad line. A key with `routes=` alone, for the target with no route: "its lines in PATH give it routes alone, not the target with no route: a line with no routes= word or with routes=* gives that".
- `pod-release`: "the signature of SHA256SUMS: WHY; nothing was replaced. If Sigstore changed its roots, download the release by hand: URL" for a chain that fails; "SHA256SUMS of TAG is signed by a signer that this program does not accept: WHY; nothing was replaced"; "the signature of SHA256SUMS: WHY; nothing was replaced" for a bad bundle. - `pod-acme`, `pod-derp`, `pod-dns`, `pod-guest`, `pod-link`, `pod-natprobe`, `pod-release`, `pod-rootfs`, `pod-supervise`, `pod-tor`: the line holds the chain of the failure, not its step alone (T-1399).
