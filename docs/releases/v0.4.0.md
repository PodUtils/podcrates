# podcrates v0.4.0

The fourth release of podcrates: `pod-dns`, the resolver, and
`pod-services`, the relays and the services of other parties as data
(milestone M1).

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-dns` | new: the resolver of podssh and podnet in one: an IP literal, the pins of the user, the system resolver, the addresses that carried a session, DNS over HTTPS (JSON and RFC 8484's wire form, over HTTP/1.1 and HTTP/2, to a resolver by its address or by its name through a proxy that resolves names), the old addresses last; the SRV records, the HTTPS record (the ECH list of `pod-tls`) and a JSON answer with its status; the default resolvers from `pod-services` | podssh, podnet |
| `pod-services` | new: one data file for each relay and service of another party (the owner's relay, DoH, plain DNS, STUN, DERP, iroh, Piping, magic-wormhole, OpenTunnel, the edge of Cloudflare, WARP, ACME, the public forwarders, Pinggy, GitHub's SSH host keys), each value with its source and date; `build.rs` checks each file against the schema and compiles the set in; a consumer reads a service by its id or the services of a kind, and lays its own files over the set (feature `overlay`) | podssh, podnet |
| `pod-proxy`, `pod-tls` | `Stream`, `ChildIo` and `Fragmenting` forward vectored writes: rustls writes each flight with one vectored write, and a stream that took only the first buffer stalled an upload over TLS | podssh, podnet |
| the others | no change | |

## How a consumer takes a crate

```toml
[dependencies]
pod-dns = { git = "https://github.com/PodUtils/podcrates", tag = "v0.4.0" }
pod-services = { git = "https://github.com/PodUtils/podcrates", tag = "v0.4.0" }
```

Each podcrates dependency of a consumer names the same tag (one source
for cargo). `adoption/CONSUMER/pod-dns.patch` takes `pod-dns` and
`pod-services` in one patch, at the commit of `adoption/CONSUMER/commit`;
the README of each crate has the adoption map of each consumer. After the
patch, run `cargo todo remap Cargo.lock` (and podnet `cargo update -w` in
`fuzz/`).

podvm takes `pod-term` with `adoption/podvm/pod-term.patch`: the line
discipline of its SSH server with no pty is `pod_term::echo`, and podvm's
own tests of the discipline run against it. Home and End move the
screen's cursor with the line's, as in podssh. The patch raises podvm's
`rust-version` to 1.99.

## Breaking

- podssh: the workaround of the vectored writes
  (`crates/podssh-ws/src/dial/bare.rs`) goes: `pod_proxy::Stream` forwards
  vectored writes.
- The hosts and the limits of other parties are reads of `pod-services`,
  not constants of the consumer.
- podnet: `-v` shows the debug lines of the pod crates too
  (`report::log_filter`); the DNS step of an IP literal is `literal`.

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (ruling Q1).

## Checks

Each crate links into a static binary on each target of the consumers
(the static probe of `ci.yml`). The trials of `adoption.yml` run the tests
of podssh and of podnet with `pod-dns` and `pod-services` in place, and the
tests of podvm's discipline with `pod-term`.
