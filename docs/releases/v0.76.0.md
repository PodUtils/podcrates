# podcrates v0.76.0

The seventy-sixth release of podcrates. It carries the extended attributes
of a layer for podrunner and podvm (the ruling "podrunner first"), and for
the gate of podssh the line of each wait of the channel of `pod-e2e` and
the hold of a move from the threshold on.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-extract` | The `SCHILY.xattr.*` records of each entry are set: on a file after its last write and before its mode, on a directory, a symlink and a hard link after it is made (with no follow of a link). The kernel decides each namespace: a refusal is named, never fatal. Each attribute that is not set is named in `LayerStats::xattrs` and `Extracted::xattrs` (`xattr::Count`), in the line `extract.layer`, and in the sidecar row of its path with its value in the hex form of `setfattr -v` (call C791). `trusted.overlay.*` and `user.overlay.*` are named and not set. Names, values and records are bounded (255 bytes, 64 KiB, 1 MiB and 1024 records an entry) (T-957, PodUtils/podrunner#317 ask 1) | podrunner, podvm |
| `pod-hostprobe` | `sys::lsetxattr` and `SYS_LSETXATTR`, for `pod-extract` (T-957) | podvm |
| `pod-session` | The hold of a move (T-958) starts in `Watch::count`, in the call that passes the move threshold, not when the task beside the link wakes: the pump takes no new byte of the application past the threshold on a slow scheduler. `Watch::moves_end` lifts the hold and clears the threshold where no move follows (a closing session, an application that ended, a failed move). On windows-2025 the move began at 899 KiB in place of 768 KiB of a 1 MiB cap (T-962, PodUtils/podssh#327) | podssh, podnet |
| `pod-e2e` | The carry of the channel says each write that takes no byte for 20 s, as the event `e2e.wait`, once for each wait, with the bytes on each side: "the application took no byte of the channel for 20 s, while N bytes wait for it; ..." and the same for the layer. `Channel::with_events` gives the events; a node's lines start with "the session of KEY: ". `operator_told` takes `told: FnMut(Event) + Send` in place of `FnOnce`: each `e2e.wait` reaches it, as `e2e.no-net` does (T-959, PodUtils/podssh#283 ask 5) | podssh |

## Breaking changes

- `pod_e2e::ends::operator_told`: `told` is `FnMut(Event) + Send`. A caller that gives a `oneshot` sender in a closure that moves it needs a sender that it can call more than once (an unbounded channel, or a `Mutex<Option<Sender>>` for `e2e.no-net` beside a line for `e2e.wait`).

## Tests and checks

- New plants: `extract-xattrs-dropped`, `e2e-t959-wait-unsaid`, `session-t962-hold-late`.
- `scripts/ci/root-uid1000-tests.sh` runs the test of the extended attributes as root and as uid 1000.

## How a consumer takes it

Each podcrates dependency names the tag `v0.76.0`; `issue-sync.yml@v0.76.0` takes `podcrates_ref: v0.76.0`.

- podrunner and podvm: a layer with `security.capability` extracts with the capability where the process can set it; else the stats, the line and the sidecar row name it, with its value, for podvm to set later. podvm: read the sidecar row's `xattrs` (call C791) and say whether its form fits your sidecar.
- podssh: change `around_told` (`podssh-cli/src/channel.rs`) for `told: FnMut`, and show `e2e.wait` at `-v`. The next hang of the gate then names the channel or its reader. Run the job `windows` of the gate again: the move begins at its threshold there too (T-962).
- podnet: the tag only.
