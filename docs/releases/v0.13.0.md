# podcrates v0.13.0

The thirteenth release of podcrates: `pod-ws`, the WebSockets of podssh
and podnet in one crate.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-ws` | new: WebSockets (RFC 6455): the frames, a session that two tasks use at once, the client of the relay over TLS, over HTTP/2's extended CONNECT (RFC 8441) and in cleartext, a WebSocket that a URL names, the server's side of the handshake, and the bridge of a session and a raw stream. Each connection goes through the caller's `Way` (its TLS context, its dialer, the reader of HTTPS records for ECH, its user agent); the crate reads no variable. `Limits` are settings (`RELAY`, podssh's, by default; `TUNGSTENITE`, podnet's). The HTTP/2 pool is a value of the caller. Each error is also a `pod_core::Failure`. The fuzz targets `ws_frame`, `ws_upgrade` and `close_reason` (T-016; call C41) | podssh (`adoption/podssh/pod-ws.patch`), podnet (`adoption/podnet/pod-ws.patch`) |
| the others | no change | |

## How a consumer takes it

Each podcrates dependency names the tag `v0.13.0`. podssh applies
`adoption/podssh/pod-ws.patch` (made on podssh `2f8e0bb`); podnet applies
`adoption/podnet/pod-ws.patch` (made on podnet `22d99a1`). Each runs the
lines of its `.run`. `crates/pod-ws/README.md`, "Adoption map", lists what
stays in each consumer. podvm needs no code change.

## Breaking

- None in a crate that a consumer takes now. podnet drops
  tokio-tungstenite and `sha1` for its WebSocket path with the patch.

## Known defect

- `pod-gsr` on Windows ARM64: a test process ends with
  `STATUS_ACCESS_VIOLATION` (T-131, open).
- Three tests of `pod-enter` fail under qemu-user only (T-149, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
