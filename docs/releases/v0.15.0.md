# podcrates v0.15.0

The fifteenth release of podcrates: `pod-session` (the resumable layer of
podssh) and `pod-wormhole` (the mailbox client and the code words) for
podssh; `pod-hold` (the hold of each connect of a payload) for podnet; the
volume and reserved paths of `pod-enter` for podvm.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-session` | new: podssh's resumable layer (64-bit offsets each way, resume through any road, replay, heartbeat, the move before the limits of the relay, the handover to a new process), UDP in a stream, the link over a `pod_ws::RelaySession` and the rule of a peer's answer. The relay's limits are `Settings` fields; the budget lines go to the caller's `Tell`; `Keeper::hand_over_with`. The fuzz targets `session_record`, `session_handover`, `udp_frame` (T-020; call C47) | podssh (`adoption/podssh/pod-session.patch`, after `pod-wormhole.patch`) |
| `pod-wormhole` | new: the magic-wormhole mailbox client over `pod-ws`, SPAKE2 and the sealed phases, the code words; the AppID and the client name are a `Config`. Fixed against the source: a hostile mailbox could make the client keep messages with no bound (now 256); the frames of a mailbox take their own limits (256 KiB, 1 MiB a message). The fuzz target `mailbox_message` (T-022; call C45) | podssh (`adoption/podssh/pod-wormhole.patch`) |
| `pod-hold` | new: the generic core of podnet's `podnet-netns`: the seccomp filter of the socket calls, the receive of a notification, the read of the child's memory (a memfd in tests), the reply seam (`Answer`), the descriptor table with the flow budget, the netns entry and the TUN; each hold reports its level (`enforced`, `advisory`, `none`) and a proof. Fixed against the source: the ioctl numbers of powerpc64le, a message with extra descriptors, a read past the end of the bytes, an address over `i64::MAX`. The fuzz target `hold_sockaddr` (T-166; call C48) | podnet (`adoption/podnet/pod-hold.patch`) |
| `pod-enter` | `GuestRoot::volume_label`: a missing `-w` inside a volume names the volume. `Names::reserved`: `Maps::new` refuses a guest side under a reserved path, and more than `MAX_MAP_PAIRS - 1` volumes (T-155, PodUtils/podvm#226) | podvm |
| `pod-hostprobe` | the seccomp probe passes the filter at its offset on a 32-bit target (it reported EFAULT on a host that allows the listener) (T-166) | `pod-hold`, podvm |
| `pod-testkit` | `host::socket_dir` and `host::socket_path`: a socket path that fits under a long `TMPDIR` (T-168) | the tests of each crate |
| the others | the tests of a Unix socket and of a move under an emulator (T-167, T-168); no change of an API | |

## How a consumer takes it

Each podcrates dependency names the tag `v0.15.0`. podssh applies
`adoption/podssh/pod-wormhole.patch`, then `adoption/podssh/pod-session.patch`
(both made on podssh `9975fe92`). podnet applies
`adoption/podnet/pod-hold.patch` (made on podnet `9e8d177`). Each runs the
lines of its `.run`. podvm moves its calls as `crates/pod-enter/README.md`,
"Adoption map", says.

## Breaking

- `pod_enter::userland::Maps::new` takes `&Names` first.

## Known defect

- `pod-gsr` on Windows ARM64: a test process ends with
  `STATUS_ACCESS_VIOLATION` (T-131, open).
- Three tests of `pod-enter` fail under qemu-user only (T-149, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).

The dry run at the tags `v0.14.0` and `v0.15.0` fails: `pod-testkit`
depends on `pod-hostprobe` and `pod-core`, and each of them took
`pod-testkit` as a dev-dependency with a version, so cargo cannot order
the packs. `main` after the tag gives these two dev-dependencies a path
only, and `scripts/check-publish-order.py` (CI and `check.sh`) finds such a
cycle. The tags need no change: the consumers take them by git.
