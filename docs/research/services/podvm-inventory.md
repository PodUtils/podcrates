## A. The relay and the reverse relay

The contract of the relay (pair, tokens, frames, close codes) is in `mux.rs`, and it goes to `pod-relay`, not to `pod-services`.

## D. Rootfs completion (`podvm-complete`)

## Notes for T-054

1. **The relay is the only service that podvm speaks to with a protocol of its own.** The rest are standard clients (OCI registries, one HTTPS fetch) or scripts. podvm has no default relay host. A default in `pod-services` would be new behavior, not a move of existing code. Rows A01 and A02 are the contract that `pod-relay` should own.
2. **The pin at `.github/workflows/secrets.yml:57` has 62 hex characters, not 64.** A sha256 has 64. We did not run the workflow. If the line is as read, `sha256sum -c` cannot match. podvm checks this on its side; it is not a podcrates question.
3. **Pin status of the fetches.** Pinned by sha256: E04, E05, E06 (kernel and modloop), G01, F06, H06. Size only: F07 (nix tarball). **No digest and no size:** E07 (Alpine v3.21 netboot), F07 (nixpkgs 22.05 archive), G04, G05, and the tags of images in F03, F04 and G07. The `docker.io` rust image (G07) is the only default that podvm pulls from Docker Hub.
4. **Third-party proxies.** Three scripts fall back to, or default to, proxies run by pkgforge: `api.rv.pkgforge.dev` (F06), `api.gh.pkgforge.dev` (I01), `forge.web.pkgforge.dev` (H07). All are test or tooling paths. None is in a shipped binary.
5. **Copies.** The Alpine kernel URL, kernel digest and alpine reference exist six times (E06). The zig version and digest exist twice (G01, G02). The zot pin exists three times (F06). The relay host exists twice (A09). If `pod-services` holds one list, these are the places that would read it.
6. **Where the value is fixed.** Hosts of images come from the caller or the image (C, D). Values fixed in code: C01, B01, B02, B04, A02. Values fixed in scripts: all of E, F, G, H.
7. **What no row covers.** `vendor/` and `references/` (skipped). The source lines of `Cargo.lock` (not read). Docs other than the files in I03 were searched, but only for the hosts above.
